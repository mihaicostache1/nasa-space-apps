# LunarWindow mission experience

The redesigned page keeps the existing overview, Explore, Compare, Learn, and Methodology anchors, with a dedicated custom-coordinate evaluation section. It retains the reference API, validation, retry/loading/error/stale-result states, lander animation, operating windows, and mission-window finder. The hero's NASA artwork rotates slowly as a decorative effect, with a pause/resume button and no rotation under reduced motion. A rectangular south-pole information panel sits on its right, moving below the image on small screens. The caption distinguishes decorative rotation and lighting from evaluated observations; the panel does not display invented mission results.

The mission explorer provides searchable verified sites, scenario A/B controls, geometric or reviewed terrain selection, a local sky dome, a selectable polar coordinate map, and computed mission insights. Only sites and terrain masks advertised by the API are available. Selecting a new site resets terrain acceptance; the reviewed Site01 frame approximation requires an explicit checkbox before a terrain request. Source details include the returned mask ID, SHA-256, DEM products, and compatibility limitation.

Mihai Costache's **Lander view** is the default workspace tab, beside Sky dome and Polar map. It renders Sun/Earth discs against the actual selected horizon, with follow-Sun, follow-Earth and free-look camera controls. Its scenario selector controls the same scenario shown by the mission controls and insights. Continuous playback and sample playback have one owner, so starting either pauses the other. Editing inputs, changing scenario/view, or applying an evaluation stops playback; results from a new request reset the renderer's camera/time state. Bracketed next sunset/Earthset, darkness, and blackout durations are accessible in expandable operational details.

Compare puts exactly four primary metrics in each scenario summary: sunlight share, Earth-visibility share, joint share, and longest joint window. Interpretation uses only returned metrics; it does not create a mission score or overall winner. Percentage-point differences require matching UTC periods, sampling intervals, and visibility rules. Clipped longest-window lower bounds are not ranked. One shared elapsed-time axis displays both scenarios' three visibility lanes; each selected observation shows its own exact UTC timestamp and sample-and-hold cadence. Different starts never imply synchronized absolute times. The keyboard slider and pointer scrubbing control the existing shared cursor.

The custom-coordinate form submits only on explicit evaluation through `POST /api/custom/evaluations`. Geometric mode requires a supplied ground elevation above the lunar sphere; terrain mode derives it from DEMs and requires frame-approximation acceptance. Coverage is described as unverified until evaluation, with explicit errors for disabled services, unsupported coverage, upstream failure, timeout, or incomplete success payloads. Generated terrain remains preliminary. Results use returned metrics/windows and a separate sample-held timeline; editing inputs marks existing results stale. See [the custom backend contract and deployment requirements](custom-coordinate-evaluation.md).

The lander renderer visually interpolates positions between archived observations; the shared cursor and visibility flags remain sample-based. Stars and surface shading are illustrative, and the Earth-phase rendering is a geometric approximation. These display effects do not create additional ephemeris samples, verified terrain relief, or more precise event times. The existing no-interpolation statements for sky-dome readouts and metrics remain in force.

The sky dome uses an azimuthal equidistant projection: zenith at centre, azimuth clockwise from north, and below-horizontal angles outside the 0° ring. The outer bound includes the returned samples and mask. Its terrain silhouette, body tracks, marker positions, and visibility states use the backend response. Markers are symbolic discs, not angular-size drawings. Track lines connect observations; neither playback nor scrubbing interpolates new ephemerides or event precision. Hover inspects an observation; dragging near a track selects it. The shared timeline slider is the keyboard alternative. Playback advances by available sample intervals and stops at the selected range end.

The map is an explicitly labeled south-pole coordinate diagram, not invented topography. It has east-positive longitude clockwise from zero at the top, equidistant latitude rings, a 50 km scale on the 1737.4 km sphere, selectable API points, pan, zoom, and reset controls. The hero is credited NASA SVS artwork with illustrative shading, independent of selected date/site. Assets and the locally served font have source/license notes in `public`.

Mission shift compares equal 24-, 72-, or 168-hour intervals at scenario A's site. Applying replaces A and B with the original and shifted intervals, resetting the playhead. Unsupported dates are blocked without API calls. The committed archive spans November 14–December 14, 2026; a six-week shift and the 30-day preset cannot be evaluated from it. Those presets show unavailable, and the slider explains out-of-coverage dates. No additional NASA data, new sites, or antenna-height models were generated.

The page supports reduced motion, keyboard focus, a skip link, native labeled controls, and mobile stacking. GPU/3D dependencies are unnecessary for this implementation: the NASA portrait provides the cinematic fallback and scientific views use SVG.

The palette uses background `#050A0E`, surfaces `#0C151D` and `#111E28`, text `#F5F7FA`, secondary text `#9AADB9`, sunlight `#FF704F`, and Earth visibility `#18B8F2`. Neutral colors handle controls and structure; orange and blue retain scientific meanings. Joint visibility uses labeled hatching combining both colors. The local Inter font remains unchanged.

Motion uses CSS and native observers, with no added animation dependency. Short entrance and section transitions support orientation; the removed portrait panel no longer controls intro completion. The Moon retains restrained pointer parallax. Visualization switches and marker positions transition without generating extra observations. Numeric values display the actual returned number. CSS and observers honor reduced-motion settings, including runtime preference changes, and content remains visible without JavaScript or observers. Sampling controls, model provenance, operational detail, and mission shifts use progressive disclosure.

Mission-shift results now show the original and revised sunlight, Earth visibility and joint availability, with signed percentage-point differences. This summary appears only after both matching requests complete. Site, observer geometry, horizon mode/mask, cadence, visibility rule and duration must agree; changed inputs hide the old summary. Longest clipped-window values are not subtracted as if their true durations were known.

An interactive horizon lesson lets the reader raise a chosen horizon against a fixed 2° Sun with a 0.27° illustrative radius. It is explicitly labeled a concept diagram, submits no API requests, and does not alter mission results. Its visibility labels are educational, separate from the selected site's observations.

Validation includes TypeScript, ESLint, production build, domain tests for projection conventions, explicit terrain acceptance and date shifts, and the browser rehearsal in `scripts/check_deployed_app.mjs`. The browser check exercises geometric and terrain requests, provenance, playhead synchronization, map selection, playback, supported shifts, unavailable six-week shifts, and mobile overflow.

Updating one scenario retains its unchanged ready partner instead of resubmitting both. Explicitly updating unchanged inputs still refreshes both; failed or interrupted slots are retried. This avoids redundant reference work without introducing a persistent browser result cache. See [loading measurements](validation/reference-loading.md).
